**Проект:** «Репрезентация психологии в кино»  
**Опирается на:** `materials/Requirements.md` (ред. 1.1), рассказ, codebook, таблицу кодирования  
**Статус:** план разработчика до Sprint 0. Открытые вопросы раздела 12 закрыты.  
**Дата:** 2026-11-10

Документ фиксирует, как из текущих материалов собрать статический сайт и выложить его на GitHub Pages. Дизайн-макеты в план не входят. Норма объёма глав C-01 на этот этап не действует: публикуем текст рассказа в том виде, в каком он есть.

В Excel два листа: «Кодирование (основная таблица)» и «Справочник (источники для выпадающих списков)». CSV — выгрузка первого листа. Источник правды для ETL — xlsx, чтобы не расходиться с выгрузкой.

Рассказ в `Репрезентация психологии в кино.md` — это вводный текст, четыре тематических блока (архетип, пространство, этика, стигма) и девять карточек произведений. Это не семь глав по 800–1200 слов и не storyboard со `scene_id`. Карточки по смыслу совпадают с таблицей и становятся черновиком страниц произведений и подписей к единицам анализа.

Codebook задаёт закрытые списки для пространства, архетипа, этики, стигмы, типа реплики и визуального тропа. Функция сцены в словаре перечислена коротко, в таблице записана свободным текстом из нескольких формулировок.

## 2. Расхождения, которые план закрывает

1. **Зерно данных.** Требования описывают `scenes` как сцену или произведение целиком. В таблице одна строка — одно произведение. У «Веб-терапии» несколько таймкодов, но одно описание и один набор кодов. Дробить строку на сцены значит выдумать границы, которых в кодировке нет.
2. **Пустая строка.** «Даг» не проходит D-05 и в рассказ не входит.
3. **Значения вне словаря.** Словарь на этом этапе не пополняется. Токен, которого нет в codebook, не становится кодом: он снимается с поля и остаётся в `note` дословной цитатой ячейки. Графики и ссылки на словарь видят только значения из codebook.
4. **Имена кодеров** лежат в столбце «Категория анализа». В публичный репозиторий этот столбец не входит, на сайте поля кодера нет.
5. **Тексты глав.** C-01 (800–1200 слов на главу) на этот этап закрыт и приёмку не держит. Семь якорей заполняются текстом рассказа и подсчётом по таблице. Счётчика слов в валидаторе нет.
6. **DOI, каталог, фильтры, сравнение, поиск, кадры, английский, формы** в этап не входят. `FilterChips` из списка компонентов требований на MVP не делаем.

### Значения таблицы, которых нет в codebook

Новые пункты словаря на этом этапе не заводятся и к ближайшим старым значениям не притягиваются. ETL оставляет в кодированном поле только токены из словаря. Снятый текст дописывается в `note` с именем поля, чтобы карточка не теряла формулировку источника. Валидатор пишет предупреждение на каждую такую ячейку и сборку не останавливает.

| Поле | Что встретилось | Что попадает в код |
| --- | --- | --- |
| `space_type` | «Гибридное пространство: домашний офис + цифровое окно» (Веб-терапия) | поле пустое, формулировка только в `note`. В матрице пространств этой единицы нет |
| `therapist_archetype` | «Исследователь-экспериментатор» рядом с «Романтизированный учёный» (Опасный метод) | в коде остаётся «Романтизированный учёный» |
| `utterance_type` | «Попытка вернуть фокус», «Оправдание», «Уточнение», «Мягкое установление границ» | в массиве остаются только типы из словаря той же ячейки, например «Совет/директива» и «Вопрос» |
| `visual_trope` | «Другое» | токен отбрасывается |
| `scene_function` | свободные формулировки | на карточке текстом, без ссылки на пункт словаря и без участия в графиках |

`scene_function` в словарь как закрытый список не входит: фразы таблицы не совпадают с короткими пунктами codebook, а новые пункты мы не добавляем.

Отдельная содержательная нестыковка для редактора, не для кода: пример codebook относит «Опасный метод» к типу «Клиника/учреждение (научно-медицинское)», а таблица и карточка рассказа кодируют «Палата/общественное пространство в клинике». На сайте остаётся значение таблицы.

## 3. Рабочие решения

| Тема | Решение |
| --- | --- |
| Единица публикации | Одна строка таблицы → одно произведение и одна единица анализа. Поле `analysis_unit`: `scene`, если есть таймкод вида `~чч:мм`; `work_overall`, если таймкод говорит «в целом» или его нет. «Веб-терапия» остаётся одной единицей, таймкод хранится строкой как в источнике. |
| «Даг» | Строка не попадает в JSON. Валидатор пишет предупреждение «пустая запись исключена». |
| Неизвестные коды | Словарь заморожен. Неизвестный токен снимается с кодированного поля, цитата остаётся в `note`, в отчёте это предупреждение. Автозамены на «похожее» значение нет. |
| Имена | Столбца с именами в публичном репозитории нет: ни в `data/source`, ни в копиях таблицы внутри `materials/`. Поля `coder` в JSON нет. Локальный полный xlsx в git не кладётся. |
| Сериалы на графиках | Все единицы входят в подсчёты. `work_overall` отличается формой маркера и подписью в легенде. Отдельной «сцены внутри сериала» график не изображает. |
| Язык | Только русский. Строки интерфейса собраны в одном модуле, чтобы второй язык позже не потребовал обхода компонентов. |
| Обратная связь | Формы нет. Почты в подвале нет. |
| Цитирование | Без имён авторов и без DOI: название проекта, год, версия датасета `1.0.0`, URL страницы на GitHub Pages. |
| Публикация | GitHub Pages, сайт проекта. Адрес вида `https://<owner>.github.io/representation-psychology/`. Сборка с `base`, подробности в разделе 4.1. |
| Стек графиков | Требования допускают D3 или Plotly. Берём inline SVG и точечно `d3-scale` там, где нужна шкала. Plotly на корпус из девяти точек не укладывается в бюджет JS 150 КБ на страницу. |
| Островки | Svelte. Гидратируются карточка-модалка, прогресс чтения и графики. Остальное — HTML. |
| Стили | Глобальный CSS и переменные. Отдельного UI-kit-фреймворка нет. До макетов — нейтральная тёмная база из раздела 8 требований, токены потом подменяются без смены разметки. |
| Хостинг | Только GitHub Pages. В `dist/` готовые HTML, CSS, JS и JSON. Серверных функций нет. |
| Главы | Семь якорей заполняются текущим текстом. Объём C-01 не проверяется и релиз не задерживает. Глава про реплики и тропы — заголовок, короткий абзац и график по таблице. |

## 4. Архитектура

Статический сайт. Браузер не ходит в API. Сборка читает xlsx, пишет JSON, Astro собирает страницы из этих JSON и markdown глав.

```text
xlsx без столбца имён
        ↓
   Python ETL  →  public/data/*.json
                        ↓
              Astro static (HTML + точечные Svelte-островки)
                        ↓
                     dist/
                        ↓
              GitHub Actions → GitHub Pages
              https://<owner>.github.io/representation-psychology/
```

Обновление корпуса: заменить xlsx, выполнить одну команду, получить новый сайт. Ручных правок JSON нет. Публикация на Pages идёт тем же `dist/`, отдельной серверной сборки нет.

### 4.1. GitHub Pages

Сайт выкладывается как project site, не как пользовательский сайт с корня домена. Все адреса живут под префиксом репозитория.

| Параметр | Значение |
| --- | --- |
| `output` | `static` |
| `site` | `https://<owner>.github.io` |
| `base` | `/representation-psychology` |
| `trailingSlash` | `always` |
| формат файлов | `directory`: маршрут `/story/` — это `dist/story/index.html` |
| артефакт деплоя | содержимое `dist/`, не корень репозитория |

`<owner>` подставляется в workflow, когда репозиторий создан. Имя репозитория в `base` совпадает с каталогом проекта. Если репозиторий назовут иначе, меняются только `base` и `site`, не шаблоны страниц.

Что из этого следует для вёрстки:

- Ссылки в шаблонах и в markdown не начинаются с корня домена. Префикс даёт `import.meta.env.BASE_URL`. Ссылка на сцену в тексте главы записывается меткой `scene:cuckoos-nest-unit`, сборка разворачивает её в `…/representation-psychology/scene/cuckoos-nest-unit/`. Так черновик главы не ломается при смене `base`.
- Якорь главы: `…/story/#archetype`.
- Файлы данных: `…/data/works.json` и соседние JSON. Кнопки «Скачать данные» ведут на эти адреса с тем же префиксом.
- Картинки, CSS и JS Astro кладёт в `/_astro/`. В `public/.nojekyll` лежит пустой файл: без него Pages обрабатывает артефакт как сайт Jekyll и не отдаёт каталоги, имя которых начинается с `_`.
- `404.html` лежит в корне `dist/`. Pages отдаёт его на неизвестный путь внутри сайта проекта. Отдельных redirect-правил нет: у Pages нет файла редиректов вроде Netlify.
- Канонические URL, sitemap и Open Graph собираются из `site` + `base` на этапе сборки. После деплоя их не переписывает сервер.
- Workflow `.github/workflows/pages.yml`: push в `main`, `contents: read`, `pages: write`, `id-token: write`. Шаги: checkout, Python, Node, `npm ci`, `npm run build`, `upload-pages-artifact` с путём `dist`, `deploy-pages`. Ветку `gh-pages` не используем.

Локальный `astro dev` поднимается с тем же `base`, чтобы ссылки в разработке совпадали с опубликованными.

Команда:

```bash
npm run build
```

Она запускает `python -m etl` и, если валидатор вернул 0, `astro build`. Ошибка валидации останавливает сборку (D-07). Отдельная команда `npm run data` гоняет только ETL, чтобы исследователь мог проверить отчёт без фронтенда.

## 6. Модель данных

Версия датасета: поле `version` в каждом JSON и в `meta.json`, для MVP — `1.0.0`. Рядом `generated_at` и имя исходного файла.

### 6.1. `works.json`

Одна запись на произведение.

| Поле | Откуда |
| --- | --- |
| `id` | стабильный латинский ключ, см. таблицу ниже |
| `title` | текст до скобок |
| `original_title` | текст в скобках; если скобок нет — пустая строка |
| `format` | `movie` или `tv_series` (в требованиях написано `TV series`; в JSON — одно машинное значение, на экране — «сериал») |
| `year_start`, `year_end` | из «1975 г.», «1999-2007 гг.», «2010–2015 гг.»; для одного года оба поля равны |
| `country` | массив, разделитель запятая |
| `genres` | массив; разделители — запятая, точка с запятой, перевод строки |
| `description` | краткое описание из рассказа, не из `scene_description` таблицы |

Описания произведений в таблице нет: там описание единицы анализа. Текст карточек из рассказа кладётся в `works.description` отдельным шагом контента (`data/source/works.md` или frontmatter), а не вырезается эвристикой из прозы. Пока редактор не разложит карточки по файлам, ETL берёт черновик из уже размеченного yaml рядом с xlsx, чтобы страница `/work/[id]` не ждала вёрстки глав.

Стабильные id (не пересчитываются при правке русского названия):

| id | Произведение |
| --- | --- |
| `cuckoos-nest` | Пролетая над гнездом кукушки |
| `analyze-this` | Анализируй это |
| `sopranos` | Клан Сопрано |
| `de-gales-hus` | Сумасшедший дом |
| `web-therapy` | Веб-терапия |
| `dangerous-method` | Опасный метод |
| `mr-robot` | Мистер Робот |
| `the-undoing` | Отыграть назад |
| `en-therapie` | В терапии |

### 6.2. `scenes.json`

Одна запись на единицу анализа. Id: `{work_id}-unit`. Пока строка одна, суффикс фиксирован. Если позже у произведения появятся отдельные сцены, добавляются `-s2`, `-s3`, а `-unit` не переименовывается.

| Поле | Правило |
| --- | --- |
| `id`, `work_id` | как выше |
| `analysis_unit` | `scene` или `work_overall` |
| `timecode` | строка после очистки пробелов; пустым не оставляем у опубликованной записи |
| `description` | `scene_description` |
| `space_type`, `therapist_archetype` | одно значение или массив, если в ячейке несколько кодов через запятую |
| `ethical_violation` | `yes` / `partial` / `no`; на экране «Да», «Частично», «Нет» |
| `stigma_level` | `high` / `medium` / `low` |
| `utterance_types`, `visual_tropes` | массивы |
| `scene_function` | массив строк, разделитель `;`, на карточке как текст |
| `note` | `general_note`, непустые `*_note` и дословные цитаты токенов, снятых с кодированных полей |

Машинные коды (`yes`, `high`) нужны графикам. Рядом в codebook лежит русская подпись. В интерфейсе человек видит подпись, ссылка ведёт на якорь значения.

Мультизначения режутся по запятой только если следующий фрагмент совпадает со словарём. Иначе фрагмент остаётся целиком. Это защищает значения с запятыми внутри кавычек вроде монтажа флешбэков. Кавычки CSV и неразрывный дефис `U+2011` приводятся к обычному дефису до сверки со словарём.

Поля `the_use_of_DH_tools` и пометки StoryMapJS / Voyant / Sutori в карточку сцены не выводятся: это внутренние идеи кодировщиков, в объёме MVP таких интеграций нет. Текст сохраняется в отчёте ETL как непропубликованное поле, чтобы его не потерять.

### 6.3. `codebook.json`

Одна запись на пару категория + значение.

| Поле | Правило |
| --- | --- |
| `id` | `{category}.{value_slug}`, например `stigma_level.high` |
| `category` | машинное имя поля |
| `value` | машинный код |
| `label` | русская подпись из словаря |
| `definition` | абзац определения |
| `example` | пример из словаря |

Категории закрытого списка: `space_type`, `therapist_archetype`, `ethical_violation`, `stigma_level`, `utterance_type`, `visual_trope`. Жанр, страна и `scene_function` в этот список не входят.

Codebook собирается из размеченного yaml (`data/source/codebook.yml`), который разработчик один раз переносит из docx-markdown. Сайт не парсит docx на каждой сборке.

### 6.4. Валидатор

Проверки, любая ошибка даёт ненулевой код:

- уникальность `id` у works, scenes, codebook;
- каждый `work_id` существует;
- у каждой сцены есть `analysis_unit`, `description`, коды справочников;
- каждое значение справочника есть в codebook;
- мультиполя — массивы JSON, не строки;
- пустые строки источника не попали в JSON;
- в публичных JSON и в `data/source` нет столбца и значений с именами кодеров;
- каждая глава ссылается минимум на два существующих `scene_id`;
- каждая содержательная глава объявляет ровно одну визуализацию из известного набора.

Предупреждения не роняют сборку и попадают в отчёт: исключённый «Даг», таймкод «сериала» у фильма «Сумасшедший дом», несколько интервалов в одной ячейке, токены вне словаря, пустой `space_type` у «Веб-терапии».

`validation-report.json` публикуется и целиком показывается на `/method`: дата прогона, версия, число произведений и единиц, список проверок, ошибки, предупреждения. Рядом человекочитаемый блок теми же фактами, чтобы страница имела смысл без чтения JSON.

Шапка: название проекта, ссылки История, Словарь, Метод, Данные. На узком экране те же ссылки в раскрывающемся блоке на кнопке, без отдельной библиотеки меню. Подвал: дисклеймер из рассказа, CC BY 4.0 на текст, CC0 на данные, MIT на код, версия датасета, ссылка на репозиторий, блок «Как цитировать» (название, год, версия `1.0.0`, URL на Pages). Почты и имён авторов нет. Skip-link на `<main>`.

«О проекте» в MVP ведёт на `/method`: отдельной страницы требования не задают, а методология и ограничения живут там.

### 7.1. История

Семь файлов `src/content/chapters/NN-slug.md`. Frontmatter:

```yaml
id: archetype          # якорь
title: 
order: 2
kind: content          # prologue | content | epilogue
scene_ids:
  - cuckoos-nest-unit
  - analyze-this-unit
viz: archetype-counts  # у пролога и эпилога можно none; у content обязателен
```

Тело — markdown редактора. Компоненты внутри текста, которые нужны уже в MVP:

- ссылка на единицу: метка `[Сестра Рэтчед](scene:cuckoos-nest-unit)`. Сборка подставляет `base` и завершающий слэш. Без JS это переход на страницу единицы, со JS клик открывает диалог и не уходит со страницы;
- врезка визуализации по id из frontmatter, один раз на главу;
- цитата и выноска, если редактор их разметит короткими директивами.

Оглавление строится из frontmatter. Прогресс — позиция прокрутки относительно статьи, островок, при `prefers-reduced-motion` без анимации ширины.

Якоря, которые дальше не меняем:

| Порядок | id | О чём глава | Опора в текущем рассказе |
| --- | --- | --- | --- |
| 1 | `prologue` | задача, корпус, дисклеймер, отсылка к методу | «О проекте» |
| 2 | `archetype` | пять образов специалиста | «Образы психологов в кино» |
| 3 | `space` | где проходит сессия | «Где обитают психологи» |
| 4 | `ethics` | да / частично / нет | «Этический рейтинг» |
| 5 | `stigma` | клеймо профессии | «Уровень стигмы…» |
| 6 | `language` | реплики и визуальные тропы | заголовок, абзац и график по таблице |
| 7 | `epilogue` | что корпус не доказывает, отсылка к будущему каталогу | дисклеймер рассказа и фраза про каталог следующего этапа |

Пролог берётся из блока «О проекте». Главы 2–5 — из четырёх тем рассказа. Карточки произведений идут на страницы `/work/`, не в главы. Глава `language` собирается из кодов реплик и тропов. Эпилог — дисклеймер и отсылка к каталогу этапа 2.

C-01 на этот этап не применяется. Главы выходят с тем текстом, который уже есть. Плашки «черновик», счётчика слов и ожидания дописанных глав нет. Сборка проверяет файл, заголовок и два `scene_id`.

### 7.2. Карточка единицы

Один компонент на страницу `/scene/[id]/` и на диалог. Поля в одном порядке: произведение, формат единицы, таймкод, описание, пространство, архетип, этика, стигма, реплики, тропы, функция, примечание. Имени кодера нет. Значение из закрытого списка — ссылка на `/codebook/#{id}`. Пустое поле (пространство у «Веб-терапии») показывает «в словаре нет» и отсылает к цитате в примечании. Функция сцены — текст без такой ссылки. Стигма дополнительно цветом, иконкой и словом (U-03).

Диалог: `<dialog>`, фокус внутри, Esc закрывает, фокус возвращается на ссылку, которая его открыла. Заголовок диалога — название произведения. Прямой заход на `/scene/[id]` рендерит ту же карточку в потоке страницы, без диалога.

### 7.3. Словарь

Секции по категориям. Внутри — определение поля и карточки значений: подпись, определение, пример, список единиц корпуса, где значение встречается. У значения несколько произведений — все ссылки. Пустой пример не скрывает определение.

### 7.4. Метод

Статический markdown редактора плюс вставка отчёта валидатора. Обязательные смыслы, даже если текст ещё короткий: что такое единица анализа в этом прототипе (строка таблицы, а не каждый монтажный кадр), как устроено кодирование, что корпус из девяти произведений иллюстрирует словарь и не является выборкой кинематографа 1975–2022, дисклеймер о репрезентации, ссылки на три JSON и `validation-report.json`.

## 8. Визуализации

Девять точек. Графики показывают распределение кодов в этом корпусе. Подпись под каждым графиком говорит, что это полный учтённый набор прототипа, а не динамика «кино вообще». Ось времени — позиции произведений, не линия тренда.

У каждого графика есть `title`, `subtitle`, `caption` в данных визуализации, не зашитые только в SVG. Под графиком — таблица тех же чисел (A-09). График в отдельном островке с динамическим импортом, чтобы он не входил в JS страниц без него.

| id | Где | Что рисует |
| --- | --- | --- |
| `corpus-timeline` | главная и пролог | произведения по `year_start`, цвет — уровень стигмы, форма точки — `scene` / `work_overall` |
| `archetype-counts` | глава архетипа | число единиц на архетип из словаря. «Опасный метод» считается один раз, как «Романтизированный учёный» |
| `space-matrix` | глава пространства | матрица архетип × пространство, ячейка — число единиц |
| `ethics-counts` | глава этики | три столбца Да / Частично / Нет |
| `stigma-timeline` | глава стигмы | тот же таймлайн, акцент на стигме |
| `utterance-counts` | глава языка | частоты типов реплик; тропы — вторая маленькая таблица под тем же заголовком главы, не второй интерактив |

Цвета стигмы задаются токенами `--stigma-high`, `--stigma-medium`, `--stigma-low` и дублируются иконкой и текстом, не только цветом. Контраст текста к фону проверяется на тех же токенах.

## 9. Доступность и бюджет

Ориентир — WCAG 2.1 AA и пороги Lighthouse из требований.

- Семантика: один `h1` на страницу, главы — `h2`, блоки карточки — `h3`, шапка и подвал — landmark.
- Клавиатура: меню, оглавление, ссылки, диалог, график не перехватывает Tab.
- Диалог по правилам F-17.
- `prefers-reduced-motion`: прогресс и появление диалога без смещения вёрстки.
- Изображений фильмов нет. Декоративные схемы — с пустым alt, если рядом есть текст; содержательные SVG — с названием и таблицей.
- Шрифт один, локальный, `font-display: swap`.
- Целевой JS страницы истории: островок диалога и один график. Полный D3 и клиентский роутер не подключаются.

Проверка перед приёмкой: клавиатурный проход истории и диалога, axe или Lighthouse на `/`, `/story`, `/scene/cuckoos-nest-unit`, `/codebook`, `/method`, ширина 375 и 1280. Отдельного визуального тест-сьюта на пиксели нет, пока нет утверждённых макетов.
