# Реестр фотографий и кадров

## Текущее состояние

В исходных материалах репозитория найдены **32 кандидатных кадров из девяти произведений**. Они перечислены в `../../data/media-assets.yml` и пока имеют статус `candidate`.

Это инвентаризация, а не разрешение на публикацию. У кандидатов ещё нужно установить первоисточник, автора/правообладателя, конкретную сцену и аналитическую цель, подготовить alt-текст, подпись и атрибуцию. Файлы остаются в `materials/new_materials/` и не копируются в публичную сборку.

Отдельная очередь фотографий (архивные портреты, исторические фотографии учреждений и документальные изображения контекста) описана в `photo-queue.md`. В репозитории пока нет подтверждённого набора таких фотографий.

## Статусы

- `candidate` — файл найден в исходных материалах; назначение и источник ещё не проверены.
- `pending_review` — установлены источник, связь с произведением и цель использования; требуется проверка прав и контекста.
- `approved` — заполнены все метаданные и зафиксировано конкретное правовое основание/подтверждение. Только такие изображения можно копировать в `public/media/` и показывать на сайте.
- `rejected` — изображение не использовать; файл остаётся вне публичной части.

## Обязательные метаданные для публикации

Для каждой записи со статусом `approved` обязательны:

1. Тип материала: `film_still` или `photograph`.
2. `work_id` и, для кадра, по возможности `scene_id`; если точная связь не установлена, она не должна выдумываться.
3. Первоисточник и прямая ссылка на страницу-источник.
4. Автор/правообладатель по доступным сведениям.
5. Конкретная аналитическая цель: какой тезис или визуальный приём показывает изображение.
6. Осмысленный `alt`, подпись и готовая атрибуция рядом с изображением.
7. `legal_basis` и заполненная запись `legal_review` с основанием, ссылкой на подтверждение, проверяющим и датой.
8. Для film still — точная связь с единицей анализа и проверенная ссылка на эпизод/таймкод (`scene_id`, `screen_time_reference`).
9. `public_path` на существующий файл внутри `public/media/`.

## Ограничения публикации

Действует правило из [финального handoff, §10.1](../design/03-final-design-handoff.md): исследовательское назначение сайта не даёт автоматического права публиковать кадры. Кадр используется только в минимальном оправданном объёме и непосредственно рядом с релевантным разбором; нужна атрибуция произведения, авторства и источника. Никаких декоративных фонов, обложек, самостоятельных фотогалерей или социальных превью из непроверенных кадров. При сомнении — не публиковать до отдельного разрешения или правовой проверки.

Для фотографий применяется тот же учёт происхождения и прав. Дополнительно проверяется, что подпись точно описывает изображённого человека/место и не приписывает человеку не подтверждённую роль или профессию.

Предварительный просмотр каждого кадра и черновые alt-описания собраны в `visual-review.md`. Они не заменяют контекстную и правовую проверку.

## Сборка

`npm run build` запускает `scripts/validate_media.py`. Проверка не допускает публикацию материалов без полного комплекта метаданных, файла в `public/media/` и подтверждённой записи проверки. Любой файл в `public/media/` должен соответствовать одобренной записи реестра.

## План интеграции

- Кадры — рядом с конкретными доказательствами на страницах единиц анализа и в главах, где визуальный приём действительно обсуждается.
- Фотографии — отдельный тип документального контекста с подписью, датировкой и источником; не подменяют кадры и не изображают экранную сцену.
- Общая подача — адаптивная фигура с alt-текстом, подписью и видимой атрибуцией. Изображения загружаются лениво.
- Сначала проверяется небольшой набор самых содержательных материалов, затем решение масштабируется на остальные кандидаты.
